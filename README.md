# Ulric Clip Calendar

![October calendar in light mode](docs/screenshots/calendar-light-desktop.png)

A social clip scheduler for creators and small brands. Upload or link a clip, plan it on a brand calendar, write the caption, and get an approval before anyone posts it. The app does not publish to Instagram, TikTok, YouTube, or Facebook.

By Ulric studio.

## Features

- Brands with a name, color, handles, default hashtags, posting cadence, and a fictional map pin.
- Month and week calendars for one brand or all brands, with drag and drop rescheduling.
- Clip upload or an external link. Uploads are probed with ffprobe, given a 9:16 thumbnail, and can be trimmed with ffmpeg in a background job. The original file stays on disk.
- If ffmpeg is missing, the file is still saved and the UI says thumbnails and trims are paused. The Docker image includes ffmpeg.
- Caption, hashtags, platform targets (IG Reels, TikTok, YT Shorts, FB), series and part, post date and time, and a stories flag.
- Approval status: draft, needs review, approved, or hold. Each clip has a comment thread and a status history.
- Review mode with keyboard shortcuts.
- CSV and PDF export for all brands or one brand.
- Public read-only share links for a brand, a date range, or both. Share pages send a noindex tag.
- Seeded demo brands: Fern & Field and Night Shift Coffee, with short videos generated by ffmpeg at startup. Those files are not committed.

## Stack

- ASP.NET Core 8 Web API
- Angular 22, standalone components and signals
- SQLite and EF Core
- QuestPDF (Community license) for the schedule PDF
- Chart.js for status and brand counts
- Leaflet and OpenStreetMap tiles for brand pins
- ffmpeg and ffprobe for probe, thumbnail, preview, and trim
- xUnit

## Run with Docker

```bash
docker compose up --build
```

Open http://localhost:8080.

The first start generates short demo videos, so give it a minute before the calendar fills in. Later starts reuse the SQLite file in the `ulric-data` volume. Delete that volume if you want a fresh seed.

## Run without Docker

API:

```bash
dotnet run --project src/Ulric.ClipCalendar.Api
```

The API listens on http://localhost:5080. In Development it also opens Swagger at http://localhost:5080/swagger. `dotnet run --project` writes the SQLite file and media folder to `src/Ulric.ClipCalendar.Api/data`. That folder is gitignored.

UI, from `web/`:

```bash
npm install
npm start
```

The dev server runs at http://localhost:4200 and proxies `/api` to http://localhost:5080.

`npm start` needs Node.js 22.22.3 or newer. ffmpeg and ffprobe should be on your PATH if you want thumbnails and trims. Without them, the banner on the calendar explains what is paused.

## Environment variables

The API reads normal ASP.NET Core configuration. Nothing here is a secret. `.env.example` lists the same names. Docker Compose already sets working defaults, so you do not need a `.env` file to start.

| Variable | Purpose | Default |
| --- | --- | --- |
| `ASPNETCORE_ENVIRONMENT` | `Development` or `Production` | `Development` for `dotnet run` |
| `ASPNETCORE_URLS` | Bind address | `http://localhost:5080` in the launch profile, `http://+:8080` in Docker |
| `ConnectionStrings__Default` | SQLite connection string | `Data Source=data/ulric.db` |
| `Storage__Root` | Folder for the database media files | `data` locally, `/data` in Docker |
| `Seed__Enabled` | Seed demo brands when the database is empty | `true` |
| `Ffmpeg__Path` | Optional full path to ffmpeg | empty, then PATH is searched |
| `Ffmpeg__ProbePath` | Optional full path to ffprobe | empty, then PATH is searched |
| `PublicBaseUrl` | Optional origin prefixed onto uploaded clip URLs in CSV export | empty, so the CSV uses a site-relative path |
| `Cors__Origins__0` | Browser origin allowed to call the API | `http://localhost:4200` |

`appsettings.json` and `appsettings.Development.example.json` carry the same safe local defaults. Copy the example if you want a local `appsettings.Development.json` of your own. Do not put secrets in either file.

## Tests

```bash
dotnet test
```

Coverage includes schedule ranges and moves, CSV columns and escaping, approval transitions, and share-token scope (including a 404 for an unknown token).

GitHub Actions (`.github/workflows/ci.yml`) builds the API, runs these tests, and builds the Angular app.

## Architecture

`src/Ulric.ClipCalendar.Api` is the HTTP API, SQLite model, ffmpeg job queue, CSV export, and QuestPDF export. Domain rules for status changes, calendar ranges, CSV rows, and share scope live in `Domain/` and do not depend on the web host.

Uploaded files go under `Storage:Root/media/{clipId}/`. A background worker runs ffprobe, writes a 9:16 JPEG thumbnail, and, when a trim or a non-9:16 source needs it, writes a separate preview. The original upload is kept.

`web/` is the Angular client. The calendar, editor, review queue, brand page, and public share page are standalone components. Theme choice is stored in `localStorage` under `ulric-theme`. With no saved choice, the UI follows the system preference.

Share links are 32 random bytes, encoded as base64url. `GET /api/public/{token}` returns only the clips inside that brand and date range. The Angular route `/s/{token}` is read only and sets `<meta name="robots" content="noindex, nofollow">`.

Demo videos are generated with ffmpeg lavfi sources the first time the database is empty. They are not stored in git. Deleting the SQLite file and the media folder reseeds them.
